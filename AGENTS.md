# storyForge

storyForge is becoming a standalone desktop app (Tauri 2, macOS first). This repository holds the app's **data core** (a plain TypeScript library over a folder of markdown, no dependency on Obsidian) and its **Tauri shell** (a Rust side that owns the disk, a file watcher, settings and app life) and its **v1 interface** (plain TypeScript and DOM, no framework) with the **numbers** (the series and novel overviews and the word-count history, read-only) and **writing sessions** (recorded when they end, shown in the history view). The design decisions live in the project's `storyForge app – decisions.md`; read it before changing anything structural. The Obsidian plugin continues, unchanged, as `storytellingForge`; its last storyForge-repo incarnation (with its interface) is the git tag `plugin-harness-final`.

Reports to read first: `docs/strip-report.md` (what was removed from the plugin and why), `docs/project-handle.md` (the design of the core, with the review rulings in §10), `docs/data-core-report.md` (what was built, and every difference from the plugin's behaviour) and `docs/safety-core.md` with `docs/safety-core-report.md` (the prose writer, recovery, backups, reconciliation, open/create and link rewriting), then `docs/tauri-shell.md` (§12 rulings, §13 as built) and `docs/tauri-shell-report.md`, then `docs/interface.md` (§12 rulings, §13 and §14 as built) and `docs/interface-report.md`, then `docs/numbers.md` (§11 rulings, §12 as built) and `docs/numbers-report.md`, then `docs/sessions.md` (§10 rulings, §12 as built) and `docs/sessions-report.md`, then `docs/story-shape.md` (§12 rulings, §13 as built) and `docs/story-shape-report.md`, then `docs/typing-aids.md` (§12 rulings, §13 as built) and `docs/typing-aids-report.md`.

## Layout

- `src-tauri/` — the Rust side. `fs/` (`storyforge-fs`, no Tauri dependency): `guard.rs` (the Rust twin of the TypeScript guard; passes `test/guard-spec/guard.json` unchanged), `containment.rs` (no write through a symbolic link that leaves the project), `ops.rs` (atomic writes, compare-then-write with `renamex_np` exchange, exclusive create/rename, `.trash/` retire, scan), `api.rs` (the one dispatch every command goes through), `watch.rs` (batching), `machine.rs`, `format.rs`, `platform.rs` (the only macOS-specific code). `src/lib.rs` is the window glue; `capabilities/main.json` grants the window only this app's own commands (`test/tauriConfig.test.ts` enforces it).
- `src/backends/tauri/` — the TypeScript Backend over those commands. `src/app/` — settings (`project.md`), `applyBatch.ts` (the watcher's batch order), `appLife.ts` (open, create, schedule, close). `sessionRecorder.ts` (one per open project: listens to the author's edits, ends a session at its last edit, checkpoints to the app's data folder, writes the session file when a session ends, finishes a crashed session at the next open). `src/diagnostic/` — the developer's diagnostic layer (development builds only; compiled out of a release).
- `src/ui/` — the interface. **Panel names:** the left panel is *storytelling | library* (a flip-sided panel; storytelling is where the app opens, library holds the codex, series, novel and archive tabs), the centre is the *workspace*, the right is the *context* panel. In `src/ui/`: `kit/` (buttons, menus, dialog, notices, inline rename), `theme/` (purposes and the one palette file), `editor/` (CodeMirror, the dressing, the save notices, the two editor slots), `faces/` (storytelling and storyForge), `overviews/` (the layer over the workspace on the storyForge face: series overview, novel overview, the data-bar primitives, debounced refresh), `screens/` (`history/` the word-count history dialog; start, new project, the reconciliation summary, Codex renaming, settings), `menu.ts` (the menu items the window answers), `model.ts` (what the interface reads from and acts through), `preview/` (the browser preview's page; `scripts/preview/plugin.ts` is its development-only server).

- `src/core/` — the library. `project.ts` (the **Project handle**: a synchronous in-memory index for reads, guarded asynchronous writes with write-through), `projectIndex.ts`, `frontmatter.ts` (parse and minimal-diff edit), `backend/` (the Backend interface, the **write guard** and `GuardedBackend`), `proseWriter.ts` (the single prose write path), `recovery.ts`, `tempTidy.ts` (leftover temporary files at open), `backup.ts`, `snapshot.ts`, `reconciler.ts`, `openProject.ts` (open and create), `linkRewriter.ts` and `linkScan.ts` (Codex rename), `sessions.ts` (the session tracker, pure, the clock passed in), `sessionFigures.ts` (the three kinds, pace and the storytelling figures, worked out when shown), `sessionFiles.ts` (the session files), then the ported data layer: `paths`, `series`, `book`, `codex`, `codexTree`, `tagRegistry`, `chapterSidecar`, `storyDetailsSidecar`, `chapterCreation`, `chapterPlacement`, `history`, `reconciliation`, `sectionBody`, `coverImage`, plus the pure maths and helpers.
- `src/backends/node-fs/` — the file-system Backend (atomic writes, `.trash/` retire). Used by tests and the CLI check now; the Tauri backend is Brief 4.
- `src/view/` — DOM-only helpers kept for the interface work (`dragReorder`, `dragReorderTree`, `dragLock`, `inkSlider`, `a11y`, `codexOpenTarget`) and `src/layout.ts`, `src/storytellingCenter.ts`. No Obsidian dependency.
- `src/cli/` and `scripts/` — the developer check: `npm run check -- <folder>` copies a folder and reports on it; it never writes to the source.
- `test/fixtures/` — synthetic projects in the 0.17 layout (`node test/fixtures/build.mjs` regenerates them; commit the result). `test/guard-spec/guard.json` — the write-guard rule table the Rust guard must also pass. `test/diskSafety/` — the disk-safety suite.

## Hard rules

- **Interface rules:** the interface reaches the core only through its APIs: prose is written only through `ProseSession` (never from a view), Codex renames go through `OpenedProject.renameNote`. **No colour outside `src/ui/theme/`**: components use named purposes (`--purpose-*`); `src/ui/__tests__/purposes.test.ts` fails on a hex, `rgb(` or palette variable anywhere else. Copy is British English in the plugin's lexicon (`docs/text-labels.md`). New dependencies need a ruling; the interface's are CodeMirror 6, Lucide and (development only) Playwright. A new Rust command may only read or reveal, or set the app's own menu items.

- **Writing sessions** (docs/sessions.md): only the author's own edits in a chapter editor count (through `ProseSession.setBody`; never reloads, link rewrites, reconciliation or Codex notes). The project folder is written **only when a session ends**, and only under `_backstage/storyforge/sessions/` (one file per month per computer, named with a random id, never the Mac's name); the session in progress lives in the app's data folder (`session/<sha>`). Typing never waits on any of it. `wordcount.md` is never touched by session tracking. Editing and short are worked out when shown, from the settings; unreliable (a paste or drop adding over 30 words) and recovered are stored. Unreliable and editing sessions are left out of the storytelling figures (the history view's days, weeks and heatmaps, and the stats panel's today and week), never out of chapter, novel or series counts or any bar. A session file that can't be read is never rewritten: the next session goes to a sibling. Ending the session is a step in the close path, after the editors flush and before the snapshot, and counts as watchdog progress.
- **The overviews and the history view write only the author's own words and choices** (docs/story-shape.md). Opening any of them writes nothing (a test compares the project folder byte for byte). What can be written from the novel and series overviews: planned lengths (the shared `lengthFields.ts`), plot notes, the novel's synopsis and the series description (through `FieldState`/`textField`, committed on blur and on every close route, never per keystroke), chapters' PoV and location lists and the default PoV (through the Codex picker), and covers. Every field write is compare-then-write against what the field last saw (`core/fieldWriter.ts`, the comparison inside the same lock as the write); a conflict, a refusal, a throw or a close that cuts a commit off puts the author's text in a recovery file (plot notes under `recovery/<book>/` as `<chapter> (plot note)`, synopsis and description under `recovery/_fields/`), never only in the field. A section write (`## Synopsis`, `## Description`) matches only a line that is exactly the heading, refuses a duplicated heading (the field is then read-only) and changes only that section; an empty field removes it. Card sizes are navigation state (machine settings). The overview is a layer over a still-mounted editor, which is `inert` while covered. Bars follow decision 8: data blue, overrun orange beyond a `bg_dim` notch, never colour alone; net-loss days are never red.
- **Covers** go through two Rust commands: `pick_cover(target)` (the target is the series or a book code, never a path; Rust shows the open panel, accepts PNG, JPEG, GIF or WebP by their first bytes up to 10 MB, writes under a temporary name, retires any existing `cover.<ext>` to `.trash/`, always, and moves the new file in create-only) and `read_cover(target, filename)` (read-only, exact `cover.<ext>` names, 10 MB). TypeScript sets or clears `cover-image` and retires the file on removal; there is no `clear_cover`. Only `ui/model.ts` calls `pickCover` and only `ui/overviews/cover.ts` calls `readCover` (architecture test). Covers are drawn from `blob:` URLs, so the content security policy's `img-src` is `'self' data: blob:` (a test keeps it in step with the sources the interface uses); the preview serves no policy, so `npm run test:cover` (Mac only, built app) checks they are really drawn. A cover that is recorded but can't be shown says so in a notice.
- **A Codex rename re-points references:** chapters' PoV and location lists and the default PoV are matched on the stored path (case and Unicode folded, never the name), updated in the form they already have, left alone when a note is archived, pruned or moved out (they show as missing), and a novel file that can't be rewritten is skipped and listed (`rekeyCodexNoteReferences`).
- **The close commits fields first:** `controller.registerCloseCommit` / `commitOnClose.ts`. A field being edited registers while it has focus; the close commits them before the editors flush, sends `close_progress`, and if a commit outlasts the limit calls its `rescue`. Planned lengths are the one exception where a lost number at quit is accepted (decision 42). `npm run test:quit` runs every route with text typed in a chapter and in a plot note, confirms the text reached the field first, and reports "not typed" retries separately from a loss.

- **Typing aids** (docs/typing-aids.md; smart punctuation, name autocorrect, shortcodes, the special-characters button): they act **only on text being typed right now**: the character just typed and at most the word it finishes, and only inside the current unbroken typed run (`typedRun`). Never on text that was already there, or that arrived by paste, drop, dictation, composition, undo, redo or a reload, and **never inside `[[links]]`, URLs, code, comments or link targets** (`core/typing/protectedText.ts`). Each keystroke's change is **one isolated undo step** (`isolateHistory`), so one ⌘Z gives back exactly what was typed; it is made through the browser's own editing (`execCommand("insertText")`, recorded by `inputHandler`) so WebKit keeps its spelling underlines (a change made through the CodeMirror state makes WebKit forget every underline in the paragraph). The rules are pure functions in `src/core/typing/` (with a fuzzer: nothing outside the run or inside protected text, every change undoes to what was typed, the word count never changes); the editor extension is `src/ui/editor/typingAids.ts` and the popup `shortcodePopup.ts`. **The Mac's own smart quotes, dashes, Text Replacements and autocorrection are off for the editor** (`platform.rs`, `register_editor_text_defaults`, per-app, in memory); the red spellcheck underlines are on. Settings are `typing-*` keys in `project.md`. `npm run test:typing` (Mac, built app) types real keystrokes and checks the result, ⌘Z through the Edit menu, a shortcode with the real Tab key and the button; `--field-shot` / `--shot` save pictures of the underlines.
- **Plot notes, the synopsis and the series description are small plain-text CodeMirror editors** (`ui/overviews/fieldCommitter.ts`, decision 47), not text areas, because a text area's undo can't keep an aid's change as its own step. They get smart punctuation only (no name autocorrect, no shortcodes), have their own history (cleared when the field is refreshed from disk), and are **never connected to the prose writer or the session tracker** (an architecture test); the Edit menu's Undo and Redo reach the focused field through `commitOnClose.ts`.
- **The window never touches the disk.** It has no file-system, shell, network or dialog permission; it calls only this app's narrow Rust commands. Rust holds the project root (chosen by the native picker or the recent list; the window can never send a path back to be treated as the project folder). Every write passes the Rust guard. The app makes no network requests.
- **Every catchable quit runs the one close** (`request_close` in `src-tauri/src/lib.rs`: stop the quit, the window flushes and saves, `quit_ready`, within 5 s; the 15 s watchdog counts from the last `close_progress`, which the window sends from real work only). Cmd+Q, the red button, the Dock's Quit, Log Out, Shut Down and SIGTERM/SIGHUP/SIGINT all reach it; the system-quit route is `applicationShouldTerminate:` added in `platform.rs`. A new route must reach `request_close`, and `finish_quit` is the only exit. `npm run test:quit` (Mac only) checks it before every release; `src-tauri/tests/quit_hook.rs` pins the tao version it was proved against.
- **Leftover temporary files** (docs/temp-tidy.md): at open, before reconciliation, never in a read-only project and never on files under a minute old, the app deals with `.<target>.<hex id>.tmp` files left by a crash. Only names matching that pattern exactly, only inside storyForge's folders and `_sf-backup/`. A backup's temporary zip and a copy identical to the file beside it are removed; anything else is copied into recovery, read back and checked, its size and time confirmed unchanged, and only then removed. Nothing that differs is ever just removed. `removeTemp` is called only from `core/tempTidy.ts`, and the guard operation `temp-remove` checks the name itself.
- **A project made by a newer storyForge opens read-only:** no writes into the folder at all (no saves, `project.md`, recovery files or backups). Only the snapshot, which lives outside the project, may be written.
- **Settings:** project settings in `_backstage/storyforge/project.md` (`format-version`, written only when a setting changes); machine settings (window, recent projects, snapshots, where you were) in the app data folder `io.github.kennyrn.storyforge`.
- **The guard table may gain rows, never lose or alter them.**

- **The disk format is frozen at 0.17.** Every path, filename and frontmatter key is read and written exactly as 0.17.1 did. No migrations. A folder in an older layout is refused (`LegacyLayoutError`), untouched. Data of removed features stays on disk, untouched.
- **Unknown frontmatter keys survive every rewrite**, and **rewrites are minimal**: changing one key changes only that key's lines (`frontmatter.ts` splices into the original text). If a YAML construct can't be rewritten minimally, **stop and report**; don't accept wider churn. Unreadable frontmatter (anchors, tags, duplicate keys, bad syntax) means the file is *unavailable*, never empty, and every write to it is refused.
- **Prose is written in exactly two places.** Chapter and Codex note bodies are written only from the author's typing, through `ProseWriter` (compare-then-write against the last-known text; the frontmatter is carried through byte for byte; on a conflict the disk wins and the author's text goes to a recovery file), or by `linkRewriter` on a Codex rename. Nothing else writes them: not reconciliation, not opening a project, not backups, not recovery. `test/architecture.test.ts` enforces who may call `proseWrite`, `linkRewrite`, `codexRename`, `createBackup` and `createRecovery`.
- **Never overwrite, never merge.** A write proceeds only if the file still holds what the writer last saw. `_sf-backup/` (backups and recovery files) is create-only, always.
- **Opening a project** (`openProject`): scan, refuse a pre-0.17 layout, load the snapshot, **reconcile (match, then recover, then prune)**, ensure without pruning, save the snapshot. It writes nothing unless something needs reconciling or ensuring, never seeds an empty folder (`createProject` does, explicitly), and none of 0.17.1's prune-at-open functions exist any more. One project per process.
- **The write guard sits below the data layer** (`GuardedBackend`); data code can't skip it. Its rules are the table in `test/guard-spec/guard.json`; change the table and the guard together, and keep the Rust guard's expectations in mind. Nothing is ever deleted: the only removals are `retire` into `.trash/` and pruning a backstage entry, which happens only after its contents are in a `_pruned` recovery file.
- **Fixtures are synthetic.** Never commit real manuscript or Codex text. Real-vault checks use `npm run check` on a local copy.
- **Attribution:** read `Code Attributions.md` before opening any reference repository. Escalate rather than copying from an unlicensed source.
- **Short-lived branches:** see `.cursor/rules/short-lived-branches.mdc`.

## Hold rules (stop and report, don't push on)

- A YAML construct can't be rewritten minimally.
- A test can't be ported faithfully.
- Compare-then-write can't be made atomic on a file system.
- A 0.17.1 behaviour being ported turns out different from how the brief describes it.
- Anything would add a file, folder or key to the project (the session snapshot lives outside it).
- Something would need a behaviour change in a kept module, not just a severed import.
- The disk-safety suite fails and the fix would widen what an operation touches.

## Commands

- Typecheck: `npm run build` (= `tsc -noEmit`). `noUnusedLocals` is off in `tsconfig.json`; turning it on permanently is an open decision.
- Tests: `npm test` (vitest, including the disk-safety suite). CI runs install, typecheck and test only.
- Check a folder: `npm run check -- <folder>`.
- Interface tests (WebKit, against the browser preview): `npm run test:ui` (separate from `npm test`; needs `npx playwright install webkit` once, and builds the Rust bridge). They must pass before every interface commit. `npm run ui:shots` refreshes `docs/interface-shots/`. CI does not run them (WebKit on a Linux runner needs system packages and the Rust bridge; run them on the Mac).
- Rust: `cargo test --workspace` in `src-tauri` (needs the toolchain; the TypeScript contract suite builds `sf-bridge` itself). Build the app: `npm run app:build`.
