# storyForge API audit — 2026-08-05

Cross-plugin audit of **storyForge as host** for formatForge (and the wider xForge surface), with emphasis on `createHostApi` / `formatting`, write-guarded theme storage, and twin-mode UX. Companion document: `formatForge/docs/api-audit-2026-08-05.md`.

**Scope:** host API v8, linked validators, presets/backups, companion lifecycle, Protections transfer.  
**Method:** code review of live sources + stress suites. Not a full Codex/right-rail product audit (those have earlier docs).

---

## Executive summary

1. storyForge is the durable host: **API version 8**, always exposes `api.formatting`, and owns vault writes for theme archives/presets.
2. Linked settings are strongly validated; compile-time checks keep `LINKED_FORMATTING_KEYS` aligned with settings + the `SfLinkedFormattingKey` union **inside this repo**.
3. The audit’s cross-repo key drift is resolved: storyForge now owns a canonical 197-key array and generates formatForge’s contract.
4. Path safety for presets/backups is good after recent hardening (case-only rename, `..` collapse on backup reads, unique dated archives, overwrite flags).
5. Removing storyForge’s formatting transfer while formatForge is enabled is intentional; standalone fallback remains when FF is absent.
6. API v8 adds whole-patch validation, one save and one restyle for bulk imports; palette uses the same path.
7. Public API docs now include the complete v2–v8 capability matrix.

```
StoryForgePlugin.onload
  └─ this.api = createHostApi(this)          # STORYFORGE_API_VERSION = 7

StoryForgeHostApi
  ├─ paths / Codex / right-rail / companion panels
  └─ formatting: StoryForgeFormattingApi
       ├─ registerCompanion / getCompanion / isCompanionActive
       ├─ get/updateLinkedSetting (+ validators)
       ├─ applyLinkedStyles / setStyleVars / getStyleDocuments
       ├─ get/updatePalette (now validated)
       ├─ save/list/readSettingsExport     # _sf-backup/
       └─ save/list/read/rename/deleteFormattingPreset  # backstage

formatForge
  └─ soft-connect → registerCompanion → themes via optional methods
```

**Write roots (enforced):**

| Root | Purpose |
|------|---------|
| `_sf-backstage/` | Presets, series metadata, plugin plumbing (`writeGuard`) |
| `_sf-backup/` | Dated zip backups + settings JSON archives |
| Library / Codex | Explicitly refused for generic writes |

## Findings

### [Resolved] Cross-repo linked-key drift

`LINKED_FORMATTING_KEYS` is now exported from `hostApi.ts` and is the source of truth. storyForge derives `SfLinkedFormattingKey` from it; `sync-formatting-contract.mjs` generates formatForge’s copy and `check:formatting-contract` verifies parity. The drifting key `editorScrollbarTrackColor` has since been retired: the manuscript scrollbar track is always transparent so the document background shows through.

### [Intentional] Protections Themes removal while formatForge is active

This is the requested ownership model, not an audit defect. storyForge removes its formatting transfer and points to formatForge whenever FF is enabled. Its standalone Themes fallback remains available when FF is absent.

### [Resolved] Per-key restyle on bulk theme updates

API v8 `updateLinkedSettings` validates every key/value before mutation, calls `updateSettings` once and restyles once. `updateLinkedSetting` delegates to the batch method for live single-control updates.

### [Resolved] Host API docs updated

`docs/formatforge-host-api.md` and formatForge’s companion document now describe v2–v8, theme storage and generated contract synchronization.

### [Resolved] Palette now uses the batch path

At v8, `updatePalette` builds a linked patch and delegates to `updateLinkedSettings`, giving it the same validation, persistence and restyle semantics.

### [P2] Dual persistence of shared size/scrollbar keys

`applyFormattingDocument` writes `SF_TEXT_STYLING_KEYS` to SF **and** merges them into FF local via `importTextStylingSettings`. Live FF UI size/palette edits while connected write SF only.

**Risk:** after disconnect, FF may reapply stale local sizes/scrollbar/palette that diverged from the last SF-linked values.

### [P2] SF Themes `importSettings` bypasses linked validators — `main.ts`

Protections apply merges by key presence only. Host API path validates enums/types; Themes import does not.

**Risk:** hand-edited vault JSON can persist invalid enums that later break UI or CSS assumptions.

### [P2] Cycling-guide keys live in FF “text styling” export section but not in `FormatForgeSettings`

`SF_TEXT_STYLING_KEYS` includes `cyclingGuide*`; those keys are not on FF settings. Import without SF silently drops them.

**Risk:** theme portability for cycling guide depends on SF being present at apply time; section naming misleads.

### [P2] Preset rename still copy+delete for distinct names

Case-only rename now uses `renameBackstagePath` (fixed). Distinct-name rename still read → write → delete. If delete fails after write, duplicates can remain.

**Risk:** low; worth a follow-up to prefer `vault.rename` whenever same folder.

### [P2] Backup uniqueness queue uses a synthetic path

`writeUniqueSettingsExport` serialises via `enqueueBackstageWrite(\`${BACKUPS_FOLDER}/.settings-export-queue\`)`. Naming is misleading for future maintainers even though the queue works.

### [P3] Formatting API always present even when companion absent

Correct by design (linked values survive FF uninstall). Callers must not assume `isCompanionActive()` implies theme UI ownership without checking formatForge separately (`isFormatCompanionActiveForSettings`).

### [P3] Large surface area in one host object

`hostApi.ts` (~900 lines) mixes Codex mutations, right-rail, and formatting. Formatting is modularised in `formattingApi.ts` types, but implementation remains inline in `createHostApi`.

### [P3] Soft-connect keepalive polls every 1s forever

Correct for hot-reload detection; minor ongoing cost.

## Strengths

- Compile-time linked-key ↔ settings alignment inside storyForge.
- Validators on every linked key; palette updates validated.
- Write guard with `..` collapse; preset owner scoping; backup read nesting/`..` rejection.
- Overwrite-required saves; concurrent same-name create serialised.
- Case-only rename safe on case-insensitive volumes.
- Unique dated archive filenames under concurrent save.
- Companion thrash / handoff / theme CRUD stress tests (API v8).
- Clear twin-mode pointer into formatForge settings for formatting.
- No P0 vault-escape / Codex-Library write hole found in audited preset/backup paths.

## Contract / versioning matrix

| Version | Formatting additions (cumulative) |
|---------|-----------------------------------|
| 2 | `formatting` companion + linked settings + palette + style vars |
| 3 | Companion panels (top-level host; not formatting-only) |

## Recommended follow-ups

1. Add `check:formatting-contract` and both plugins’ stress suites to CI. *(Still open — no PR CI workflow yet, release workflow only.)*
2. Route standalone storyForge Themes imports through the same validators as the host API. **Done** — `importSettings` now calls `findInvalidLinkedSettings` before merging.
3. Prefer `vault.rename` for all same-folder preset renames. **Done** — `renameSettingsPreset` uses `vault.rename` whenever the target name is free.
4. Rename the generic guarded-write queue helper so backup serialization is clearer. **Done** — the synthetic key is now a documented `SETTINGS_EXPORT_UNIQUENESS_LOCK_KEY` constant in `backup.ts` instead of an inline dot-file-looking literal.

Items 2–4 (all P2) and the companion full-codebase audit's P1 (cover-image path sanitization, already fixed in `book.ts` by the time of this pass) were closed out in a follow-up pass on 2026-08-05; see `full-audit-2026-08-05.md`'s "Resolution" section for the complete list. Items not owned by storyForge alone (dual persistence of shared size/scrollbar keys; cycling-guide keys in FF's text-styling export section) remain formatForge-repo-side follow-ups.
